# HCM / LMS Smartis — бэклог

**Полное название:** HCM / LMS Smartis — система управления и обучения персонала.

Статус: базовые LMS- и HCM-модули реализованы; интеграции, массовый кадровый импорт и производственная подготовка остаются в работе.

## Цель

Расширить существующую Smartis LMS до единой HCM / LMS-системы:

- обучение, курсы, тесты и траектории;
- реестр сотрудников и кадровых изменений;
- аналитику по персоналу и обучению;
- ATS — базу кандидатов с настраиваемой воронкой;
- перевод кандидата в сотрудника без повторного ввода данных.

HR и ATS развиваем как разделы текущего приложения, а не как отдельные сервисы для пользователя. Используем существующий стек React + Django REST + PostgreSQL + Docker, общую авторизацию и дизайн Smartis LMS. Streamlit и Replit Auth не добавляем.

## Принцип единой системы

- Одна точка входа и одна учётная запись.
- Единая навигация: Главная, Обучение, Сотрудники, Подбор, Аналитика, Администрирование.
- Общие справочники отделов, должностей, компетенций и пользователей.
- Единая карточка человека: кандидат → сотрудник → пользователь LMS.
- Курсы, тесты, ИПР и кадровые данные связываются без выгрузок между внутренними модулями.
- Права определяют доступные разделы и поля, но не требуют входа в другую систему.
- Один Docker-комплект и одна база PostgreSQL с разделением данных по доменным модулям.

## Общий фундамент — этап 0

- Общие справочники: юридические лица, департаменты, отделы, должности, грейды, компетенции.
- Роли: администратор, HR-менеджер, руководитель отдела.
- Ограничения одновременно на уровне разделов, строк и полей.
- Зарплата разделяется на оклад, ежемесячную и квартальную премии и скрыта без отдельного разрешения.
- Неизменяемый журнал действий: кто, когда и какие поля изменил.
- Вход только для заранее созданных пользователей с корпоративной почтой `@smartis.bi`.
- Политика хранения персональных данных, резервного копирования и удаления должна быть согласована до загрузки реальных данных.

## Этап 1 — реестр сотрудников (HR MVP)

- Карточка сотрудника: ФИО, дата рождения, образование, дата начала работы, компетенции, должность, грейд, отдел, статус и дата увольнения.
- Автоматический расчёт возраста и полного стажа.
- История грейдов, должностей, отделов и переводов с источником изменения.
- Ручное создание и редактирование карточки.
- Импорт сотрудников из XLSX/CSV с предпросмотром, сопоставлением колонок и отчётом об ошибках.
- Ежемесячный импорт кадровых изменений из 1С без дублирования событий.
- Поиск и фильтры по отделу, должности, грейду, возрасту, стажу и компетенциям.

Критерий готовности: HR может загрузить таблицу, проверить изменения, подтвердить импорт и увидеть корректную историю сотрудника.

## Этап 2 — связь с обучением и аналитика

- Связать сотрудника с существующим пользователем LMS.
- В карточке сотрудника показывать курсы, траектории, тесты, попытки, скорость и процент прохождения.
- Чек-листы, ежемесячная оценка и процент ИПР.
- Дашборды: численность, возраст, стаж, половозрастной состав, движение и текучесть.
- Разрезы по компании, департаменту, отделу, должности и грейду.
- Аналитика качества обучения по результатам тестов, попыткам и срокам.
- Временный импорт данных iSpring, пока две LMS работают параллельно; затем источником становится Smartis LMS.

## Этап 3 — ATS и база кандидатов

- Карточка кандидата: контакты, желаемая должность и зарплата, навыки, опыт, источник, ответственный HR и целевой отдел.
- Ручное создание и загрузка резюме DOCX/PDF/TXT.
- Безопасное распознавание резюме с предварительным подтверждением найденных полей.
- Новое резюме дополняет опыт и создаёт событие истории, а не молча перезаписывает данные.
- Настраиваемые администратором этапы воронки.
- Канбан с drag-and-drop, следующим действием и сроком.
- Комментарии и неизменяемая история этапов и правок.
- Поиск и фильтры по этапу, вакансии, отделу, источнику, возрасту и зарплате.
- Руководитель видит только назначенных ему кандидатов и может оставлять обратную связь.

Начальные этапы: Новые → Связь → Интервью → Тестовое → С руководителем → По ценностям → Рекомендации → Оффер → Оформление → Вышел на работу.

## Этап 4 — найм и коммуникации

- Реализовано: планирование собеседования, сценарий вопросов, список участников, индивидуальные оценки и итоговое решение HR.
- Реализовано: загрузка оффера, его согласование и фиксация принятия или отказа кандидата.
- На этапе «Вышел на работу» — мастер создания сотрудника с выбором даты выхода, отдела, должности и грейда.
- Защита от создания дубликатов сотрудника.
- Письма кандидату через корпоративную почту с сохранением факта отправки и шаблона сообщения.
- Встречи через Яндекс Календарь/Телемост после проверки доступных API и корпоративных разрешений.
- Интеграция hh.ru только через разрешённый API или официальный экспорт; HTML-парсинг не считать основным вариантом.

## Предварительный скелет данных

- `Employee`, `EmployeePositionHistory`, `EmployeeGradeHistory`, `Compensation`, `Competency`.
- `HrImportBatch`, `HrImportRow`, `AuditEvent`.
- `Candidate`, `CandidateContact`, `CandidateExperience`, `CandidateResume`.
- `RecruitmentStage`, `CandidateStageEvent`, `CandidateComment`, `CandidateAssignment`.
- `Offer`, `Interview`, `OutboundMessage`.

## Важные решения до разработки

1. Утвердить владельца и правила доступа к зарплатам и персональным данным.
2. Получить реальные шаблоны XLSX/CSV и ежемесячного отчёта 1С.
3. Определить способ сопоставления сотрудника между 1С, iSpring и Smartis LMS.
4. Проверить доступность API hh.ru, iSpring и Яндекс для корпоративного аккаунта.
5. Утвердить обязательные этапы воронки и правило определения дублей кандидатов.
6. Решить, какие данные руководитель отдела видит по сотрудникам и кандидатам.

## Не входит в первую версию

- Автоматическое принятие кадровых решений на основе ИИ.
- Самостоятельная отправка оффера без подтверждения HR.
- Неконтролируемый парсинг закрытых страниц hh.ru.
- Хранение реальных персональных данных в демонстрационной среде.
