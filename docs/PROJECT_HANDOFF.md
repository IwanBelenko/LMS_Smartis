# Передача проекта HCM / LMS Smartis

Дата актуализации: 3 августа 2026 года.

## Где находится проект

- рабочий каталог: `LMS_Smartis`;
- активная ветка: `codex/publish-smartis-lms`;
- стек: React + TypeScript, Django REST Framework, PostgreSQL, Caddy, Docker Compose;
- полное название: HCM / LMS Smartis — система управления и обучения персонала.

Перед началом новой задачи выполнить `git status` и `git log -1 --oneline`.

## Текущее состояние

Работают LMS, конструктор лонгридов, SCORM 1.2, траектории, тестирование,
прохождение курсов, роли, реестр сотрудников, оргструктура, HR-аналитика,
кадровые документы, отсутствия, подбор, собеседования, офферы, адаптация,
оценка, импорт сотрудников и временная синхронизация результатов iSpring.

Интерфейс ориентирован на desktop, использует Roboto, светлую/тёмную темы,
фирменный цвет `#7EA935` и логотип Smartis. Текущий локальный адрес разработки —
`http://localhost:5173/`, когда запущен Vite.

Полный перечень реализованного находится в `README.md`, HCM-бэклог — в
`docs/HR_BACKLOG.md`.

## Последний завершённый этап

Проведён аудит сохранности production-данных и базовой безопасности:

- PostgreSQL и media хранятся в отдельных Docker-томах;
- deployment создаёт backup перед запуском API и миграций;
- добавлен защищённый CSV-экспорт сотрудников;
- поля компенсации экспортируются только при отдельном разрешении;
- закрыта прямая раздача кадровых документов и файлов офферов;
- скачивание оффера проходит через API с проверкой роли;
- production блокирует слабые секреты, стандартный пароль БД и `ALLOWED_HOSTS=*`;
- добавлены security-заголовки и тесты разграничения доступа.
- API-токены ограничены 12 часами, ротируются при входе и отзываются по истечении.

Регламент: `docs/DATA_SAFETY_AND_SECURITY.md`.

## Приоритеты следующего этапа

1. Проверить восстановление production-backup на отдельном стенде.
2. Настроить ежедневные внешние резервные копии, мониторинг диска и ошибок входа.
3. Заменить root-пароль сервера, настроить SSH-ключ и отключить вход root по паролю.
4. Добавить загрузку и защищённое хранение резюме кандидатов.
5. Доработать поиск и фильтры реестра сотрудников.
6. После получения доступов подключить API iSpring, Яндекс и при необходимости hh.ru.
7. Перед настоящими персональными данными провести пентест.

Геймификация «Сеть развития» отложена: прототип паутины существует, но не должна
перекрывать задачи production-готовности и безопасности.

## Правила продолжения

- сохранять существующий дизайн и архитектуру без переписывания проекта с нуля;
- проверять права не только в интерфейсе, но и в queryset/API для каждого ID;
- не добавлять реальные персональные данные в локальную или временную среду;
- не коммитить `.env`, пароли, токены, SSH-ключи и резервные копии;
- перед изменением схемы данных создавать backup и использовать совместимые миграции;
- сохранять пользовательские изменения в грязном worktree и не применять destructive Git-команды.
