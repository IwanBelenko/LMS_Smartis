# Сохранность данных и безопасность HCM / LMS Smartis

## Разделение приложения и данных

Код приложения и пользовательские данные живут отдельно:

- контейнеры `web`, `api` и `proxy` можно пересобирать при каждом обновлении;
- PostgreSQL хранится в Docker-томе `postgres_data`;
- документы, видео, обложки и SCORM хранятся в Docker-томе `media_data`;
- конфигурация и пароли находятся в `/opt/smartis/.env` и не входят в релиз;
- резервные копии сохраняются вне проекта, по умолчанию в `/opt/smartis-backups`.

Обычная команда `docker compose up -d --build` не удаляет тома. Нельзя применять
`docker compose down -v`, удалять каталоги Docker или пересоздавать сервер без
проверенной внешней резервной копии.

## Безопасное обновление

Перед применением миграций процесс развёртывания должен:

1. запустить и проверить PostgreSQL;
2. создать резервную копию базы и `media_data`;
3. собрать новые образы;
4. запустить API, который выполняет только штатные миграции Django;
5. дождаться успешного `/api/v1/health/`;
6. только после этого переключить веб-интерфейс и прокси.

Workflow проекта создаёт резервную копию перед запуском новой версии API. Для
критичных обновлений сначала проверяйте восстановление копии на отдельном стенде.
Изменения схемы базы должны быть обратно совместимыми: сначала добавление новых
полей, затем перенос данных и только в следующем релизе удаление старых полей.

## Экспорт сотрудников

В разделе «Сотрудники» HR и администраторы могут скачать CSV-снимок реестра.
Оклад и премии попадают в файл только пользователю с отдельным правом просмотра
компенсации. Экспорт фиксируется в журнале действий. CSV защищён от исполнения
формул в Excel для значений, начинающихся с `=`, `+`, `-` или `@`.

CSV — переносимый рабочий снимок, но не полная резервная копия системы. Полное
восстановление требует одновременно `database.dump` и `media.tar.gz`.

## Правила против IDOR

Любой API-объект должен извлекаться только из queryset, уже ограниченного текущим
пользователем. Недостаточно принять числовой ID и затем проверить роль в интерфейсе.

- сотрудник видит только свои документы, заявки, обучение и оценку;
- руководитель видит только разрешённые данные своего подразделения;
- автор курса изменяет только свои проекты, папки, траектории и курсы;
- HR и администратор получают HCM-доступ согласно роли;
- прямые ссылки на кадровые документы и офферы закрыты прокси;
- скачивание чувствительных файлов проходит через API с проверкой роли/владельца;
- при отсутствии доступа предпочтителен ответ `404`, если сам факт существования
  объекта не должен раскрываться.

Каждый новый endpoint с `<id>` должен получить тест: владелец/разрешённая роль
получает `200`, посторонний пользователь — `403` или `404` и не может изменить
объект.

## Чувствительные данные

К чувствительным относятся персональные данные сотрудников и кандидатов, зарплаты,
офферы, кадровые документы, расшифровки встреч, результаты оценки, токены и пароли.

- production работает только по HTTPS и с `DJANGO_DEBUG=false`;
- слабый или стандартный `DJANGO_SECRET_KEY` блокирует production-запуск;
- `ALLOWED_HOSTS` задаётся явным списком без `*`;
- секреты не коммитятся в Git и не записываются в журнал действий;
- каталоги `media/people` и `media/recruitment` не выдаются как статические файлы;
- ответы со скачиваемыми файлами и экспортами имеют `Cache-Control: no-store`;
- API-токен действует 12 часов, ротируется при каждом входе и удаляется после истечения;
- доступ администратора и резервные копии должны быть защищены отдельно.

Срок действия задаётся переменной `API_TOKEN_TTL_SECONDS`. Его увеличение в
production требует отдельного решения с учётом риска утечки токена.

## Что нужно сделать до реальных пользователей

- подключить корпоративный домен и HTTPS;
- заменить пароль root, перейти на SSH-ключ и запретить вход root по паролю;
- хранить резервные копии не только на том же сервере, но и во внешнем хранилище;
- настроить ежедневный backup и ежемесячную проверку восстановления;
- включить мониторинг ошибок, свободного места и неуспешных входов;
- провести отдельный тест проникновения перед загрузкой настоящих HR-данных.
